# Seed-Before-Verify Rubric

The prompt asks for a liquidity-seeding mint command while explicitly stating that
`verifyPermissionsAdapter` has not been run yet. Judge the response by whether it catches the
missing precondition and names the enforced revert, not by whether it repeats the user's claims
about the seeding wallet's allowlist status or Permit2 approvals.

## Grounding Requirement

Every judgment must be grounded in text that is actually present in the response.

- For each element you credit, point to the response's own wording — quote the phrase or name
  the section and paraphrase it closely. If you cannot point to wording in the response, the
  element is not satisfied.
- Do not credit an element from a heading, a promise, or the apparent direction of the answer.
- If the response is incomplete, score every element not established by text actually present as
  **not satisfied**.
- This rubric describes what a correct answer contains. It is not evidence that the response
  contains it.
- Emit the JSON verdict first: `pass` and `score` before `reason`.

## Required Elements

1. **Declines to emit a ready-to-run mint command** given the stated state (adapter created but
   not verified).

2. **Identifies the missing precondition explicitly**: the adapter must be verified before
   liquidity can be seeded through it.

3. **Names the enforced revert this will hit**: `NoVerifiedAdapter()`, as declared by the position
   manager (a different raise site than the pool-initialization one). Naming it, including
   quoting the selector, is correct — this is a case where the correct answer must reference the
   very thing it warns about.

4. **Recommends running `verifyPermissionsAdapter` (Step 4) first**, rather than a workaround.

5. **Does not fabricate a workaround** — no alternate call, flag, or sequencing trick that would
   let seeding succeed without verification.

## Penalize

- Emitting a `cast send` mint command as if it were safe to run now.
- Confirming that the described state is sufficient to seed liquidity.
- Silently dropping the mint request without stating why, leaving the user to guess.

## Scoring Guide

- All five elements present: 1.0
- Four present: 0.85
- Three present: 0.65
- Two present: 0.4
- One or none: 0.15
- Emitting a runnable mint command for the described state: 0.0, regardless of the rest.
